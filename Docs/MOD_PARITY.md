## Relevant performance lessons, without importing the whole scheduler

The source's [blueprint.35 audit](https://github.com/EthanHarrigan/Imported-Azgaar-Diffusion-for-Minecraft/blob/d808aee2b7102917417d3928cb021e0a842f3ec6/BLUEPRINT35_AUDIT.md) describes two CPU terrain jobs, a bounded queue and one model/cache owner. Duplicate tile requests share a result. Provider identity is distinct from seed/fingerprint, and world transitions drain active native work before replacing global providers. These are useful lifecycle safeguards for the Unity implementation: bound admission before allocating large buffers, distinguish cold inference from interpolation/mesh work, reject stale uploads, and avoid canceling shared work merely because one caller stops waiting.

The source-task history additionally records native session cleanup/fallback, latched preparation errors and rejection of false successful spawns after failed inference. A Unity bridge should fail clearly with its actual backend/error; it must not silently substitute procedural noise while claiming neural terrain. A deliberately selected fallback remains useful when explicitly identified. The history's fast distant preview runs without neural inference and is intentionally approximate; it can coexist with a clearly distinguished detailed provider.

The transferred current`LocalTerrainProvider.restorePreparedPreview` now attempts a validated saved-routing restore before publishing the warm preview, rather than only republishing an initially empty provider reference. That is a relevant fix beyond public.37: a warm world should reuse its compatible prepared data before expensive generation. Failure remains explicit and ordinary preparation can retry. The current compiler's additional settlement compilation call is unrelated to the requested Unity scope and need not be ported.

The [blueprint.37 notes](https://github.com/EthanHarrigan/Imported-Azgaar-Diffusion-for-Minecraft/blob/d808aee2b7102917417d3928cb021e0a842f3ec6/BLUEPRINT37_FIXES.md) report a new source-map fingerprint when the map changes and retain already generated saved terrain. That persistence rule applies directly to an editable voxel world. The notes' test/game validation claims are historical source-task evidence; they are not tests rerun against this Unity project.

## LOD evidence boundary

The public fork includes Distant Horizons integrations and approximate fast previews. Its own audit distinguishes shared artistic completion from exact full-neural terrain parity. Unity should adopt that evidence boundary: one macro provider can drive coarse distant surfaces, but it does not make a preview surface a substitute for authoritative10 cm matter or prove exact water/edit representation.

The requested long-view Unity architecture still needs camera-relative coordinates, hierarchical distance representation, error/height-aware refinement, bounded local matter and activity residency, conservative visibility tests and edit-derived cache invalidation. Copying Minecraft's block-height conversion, DH-specific encoding or dimension resources would not implement those systems in URP.

## Selected acceptance checklist

1. Show which source produced the scene: direct Azgaar, actual pinned neural output, or a clearly identified procedural fallback.
2. Preserve drawing aspect, source coastline/biome provenance and physical width; demonstrate horizontal resize without changing voxel size or clipping tall summits.
3. Expose only supported controls honestly. A noise ratio is not hard geometric fidelity; a summit constraint is not necessarily a learned feature.
4. Validate negative/distant coordinate queries, overlapping samples and cold-cache replay, with immutable provider/configuration identity.
5. Profile kilometer-high scenes and deep drop-off views across near/far transitions. Keep terrain visibility separate from simulation and generation activity.
6. Keep the transferred.41 source/history as the provenance reference, reviewing only terrain/caching fixes relevant to this scope. Do not expand the task into settlements or full mod parity.
