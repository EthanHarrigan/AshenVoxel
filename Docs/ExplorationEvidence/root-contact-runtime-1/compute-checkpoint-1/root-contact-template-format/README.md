# Compact root companion-template candidate

This isolated `AVRC0001` cache carries the two reviewed mature redwood templates,
their complete canonical wood context through row32, original coarse-reducer
chunk order, and fixed representatives for all five mesh LODs. It is not installed
in Assets and does not change AVPM4, the world file, population generation, or
gameplay snapshots. No whole tree is generated by the reader.

`export-manifest.json` pins all original inputs against previous frozen evidence.
The export removes a recorded placement's unused target-height field from root
columns. Actual targets remain per-instance terrain queries; the shared cache
does not embed the two test placements' ground heights.

The caller supplies a trusted full-file SHA256, matching pack SHA256 and model ID.
The format also has a payload checksum. These pins bind the data to the reviewed
authoring inputs; a checksum alone cannot certify arbitrary replacement geometry.
The reader does not regenerate the canonical tree to prove an untrusted export.

The 16-byte header is ASCII `AVRC0001`, little-endian int32 version1 and payload
length. A32-byte SHA256 follows, then at most2MiB payload. Counts and remaining
record bytes are checked before arrays are allocated. Constructors enforce the
root/context domains, colors and duplicates; the reader checks complete matching
root/context seam rows29/30, rank domains, fixed sample fields and all five cuts.
Every declared byte must be consumed. No strings or arbitrary asset paths are
decoded. The stream stays caller-owned; read/callback time is not bounded by a
byte cap. Instantiated CLR dictionaries/objects and constructor copies require
separate residency accounting; file size is not a runtime memory guarantee.

Migration decision: this is a replaceable cache with strict version rejection.
Unsupported versions, invalid data, mismatched pack/model/manifest or missing
files retain the complete canonical-tree fallback. Regeneration must use reviewed
source and create a new manifest. No historical gameplay save is migrated.

The bridge uses the two recorded resulting root fixtures as input; it does not
